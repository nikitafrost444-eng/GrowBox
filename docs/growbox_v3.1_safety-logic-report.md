## 1. Что проверялось и чем

Тепловой расчёт отвечает на вопрос «сколько градусов». Прогон safety-логики
отвечает на другой вопрос: **при любом исходе аварии система не остаётся
в опасном состоянии**. Для этого взята дискретная модель управления:

```
датчики  ──►  правила (R1..R9)  ──►  исполнители  ──►  инварианты (H1..H8)
   t_cam, t_din, тахо вентилятора,        ГР.1 свет        свойства, которые
   датчик протечки, RCD3, РКН,            ГР.2 вентиляция  обязаны выполняться
   сеть 220 В, кнопка СТОП                ГР.3 вода        ВСЕГДА
                                            ГР.5 обогрев
```

Правила применяются до неподвижной точки (могут дополнять друг друга:
например, «протечка → RCD3 → обесточить ГР.3» — это два шага).
После сходимости проверяются инварианты.

## 2. Инварианты безопасности

| ID | Требование | Какой риск закрывает |
|---|---|---|
| **H1** | свет не горит без работающей вентиляции | терморазгон камеры за минуты (300 Вт при нулевом воздухообмене) |
| **H2** | при протечке вода перекрыта (клапан закрыт, помпа OFF) | затопление комнаты |
| **H3** | при сработавшем RCD3 группа воды обесточена | поражение током через воду |
| **H4** | нет «блуждающего» открытого клапана без питания | неконтролируемая подача воды |
| **H5** | обогрев ГР.5 не работает при t_din ≥ 55 °C | пожар/деградация щитка |
| **H6** | свет гаснет при t_cam ≥ 33 °C | перегрев растений и драйвера |
| **H7** | кнопка СТОП обесточивает свет и воду | ручной рубильник работает как заявлено |
| **H8** | пропала сеть → свет погашен аппаратно | свет остался, вентиляция сдохла → терморазгон |

| Ложное срабатывание RCD3 | PASS |
| ГР.2 обесточена, свет остался | PASS |

**Нарушений инвариантов: 0.** Правила R1..R9 самосогласованы: каждая авария
доводит систему до безопасного состояния, а не оставляет её «висеть».

Ключевые цепочки, которые подтвердились:

- **пропала сеть** → РКН гасит ГР.1 → ГР.3 обесточена, клапан NC закрыт →
  на ИБП остаются вентиляция и электроника (~1,0–1,2 ч автономности);
- **протечка** → RCD3 / датчик → ГР.3 OFF, клапан закрыт, помпа OFF →
  свет и вентиляция продолжают работать (шкаф «дышит», не гаснет целиком);
- **отказ вентилятора** → свет OFF + тревога (главная защита H1);
- **отказ датчика температуры** → консервативный режим: свет OFF, вентиляция 100 %.

## 4. Найденные расхождения в документации (к правке)

Прогон формализовал логику, и при сверке с текстом
[`growbox_v3.1_electrical-safety.md`](growbox_v3.1_electrical-safety.md)
всплыло **6 расхождений**. Все печатаются в протоколе при каждом запуске скрипта.

| # | Где | Суть | Что сделать |
|---|---|---|---|
| **FIND-01** | §5 ИБП | «при пропаже сети сохраняем клапан воды ON», но клапан в ГР.3, а ГР.3 не на ИБП | убрать строку; зафиксировать: ГР.3 обесточивается, клапан NC закрывается — это и есть fail-safe |
| **FIND-02** | §8 СТОП | «СТОП разрывает ГР.1/2/3/5, но не клапан воды» — но клапан питается из ГР.3 | убрать «и не клапан воды»: СТОП перекрывает воду (вариант безопаснее) |
| **FIND-03** | §4 Мокрая зона | отсечка воды описана только через RCD3, а протечка без касания токоведущих частей RCD3 не вызовёт | добавить правило «датчик протечки → закрыть клапан + помпа OFF» независимо от RCD3 |
| **FIND-04** | §7 Термоконтроль | не описано поведение при отказе датчика температуры | добавить: отказ датчика → свет OFF, вентиляция 100 %, тревога |
| **FIND-05** | §5 таблица ИБП | строка «свет + вентиляция + электроника 401 Вт» подразумевает свет на ИБП, которого там нет | переименовать в гипотетическую или убрать; реальный расчёт — 100 Вт → ~1,0–1,2 ч |
| **FIND-06** | §5 | требование «свет гаснет аппаратно через РКН» есть, а зеркального «отказ вентилятора → свет OFF аппаратно» нет | зафиксировать: тахосигнал вентилятора → реле в разрыве ГР.1 (закрывает H1) |

> Все шесть — это правки текста документа, а не переустройство железа.
> Железо в проекте спроектировано правильно (клапан NC, 5 групп, УЗО типа A),
> противоречия — в формулировках.

## 6. Как перепроверить

```bash
python3 docs/safety_logic_sim.py                       # прогон, exit 0 = всё ок
python3 docs/safety_logic_sim.py > models/v3.1/reports/safety_logic.txt   # обновить протокол
python3 docs/airflow_thermal_calc.py                   # тепловая половина ⑧
```

При изменении правил (новая группа, новый датчик) — сначала добавить сценарий,
потом инвариант, потом править железо. Порядок такой, чтобы правило нельзя
было «забыть» при перепроектировании.
